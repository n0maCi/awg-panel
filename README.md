# AWG Panel

Минимальная self-hosted панель для AmneziaWG. Один Docker-контейнер поднимает userspace-интерфейс AmneziaWG, API и React-интерфейс.

Возможности:

- авторизация по одному паролю; в контейнер передаётся только bcrypt-хеш;
- AWG 1.5, 2.0 и 3.1 через `AWG_VERSION`;
- настройка адреса интерфейса, порта, DNS, MTU, маршрутов, keepalive и сетевого устройства через Docker Compose;
- создание, скачивание и QR-код клиентских конфигураций;
- мгновенное включение и отключение клиентов;
- переносимый бэкап серверных ключей, параметров AWG и всех клиентов;
- primary/replica-кластер с автоматической REST-репликацией конфигов между серверами;
- автоматическая подстановка нового IP/домена после восстановления на другом сервере;
- userspace `amneziawg-go`, поэтому специальный модуль ядра не требуется.

Проект вдохновлён [w0rng/amnezia-wg-easy](https://github.com/w0rng/amnezia-wg-easy), но написан отдельно и использует актуальные userspace-инструменты AmneziaWG.

## Быстрый запуск

Требования: Linux-сервер, Docker Engine с Compose v2 и доступный UDP-порт.

```bash
cp .env.example .env
```

Сгенерируйте bcrypt-хеш пароля. Вариант без установки Node.js:

```bash
docker run --rm httpd:2.4-alpine htpasswd -bnBC 12 "" 'ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ' | tr -d ':\n'
```

Или из исходников проекта:

```bash
npm install
npm run password -- 'ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ'
```

Вставьте результат в `.env` целиком и обязательно оставьте одинарные кавычки — они не дают Docker Compose интерпретировать символы `$`:

```dotenv
PASSWORD_HASH='$2b$12$...'
AWG_HOST=198.51.100.25
AWG_VERSION=3.1
```

Запустите панель:

```bash
docker compose up -d --build
```

Web UI будет доступен по адресу `http://IP_СЕРВЕРА:51821`, VPN — на `51820/udp`.

## Версия протокола

В `.env` или непосредственно в `docker-compose.yml`:

```dotenv
AWG_VERSION=1.5  # совместимость со старыми клиентами
AWG_VERSION=2    # S3/S4, диапазоны заголовков и I1-I5
AWG_VERSION=3.1  # header protection, padding, таймеры и random trailers
```

Образ всегда собирается с актуальной реализацией, понимающей все три формата. Переменная меняет именно набор параметров в серверном и клиентских конфигах. После смены версии перезапустите контейнер и заново скачайте клиентские конфиги: параметры обеих сторон должны совпадать.

Для AWG 3.1 нужен совместимый клиент, например AmneziaVPN 5.0.1.5+ или нативный клиент AmneziaWG 3.1. Встроенные безопасные параметры генерируются при первом старте и затем сохраняются в `/data/state.json`.

## Переменные интерфейса

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `AWG_HOST` | обязательно | Публичный IP или DNS-имя сервера |
| `AWG_PORT` | `51820` | UDP-порт AWG внутри и снаружи контейнера |
| `AWG_INTERFACE` | `awg0` | Имя интерфейса |
| `AWG_ADDRESS` | `10.8.0.1/24` | Адрес и подсеть интерфейса |
| `AWG_DEVICE` | `eth0` | Интерфейс контейнера для NAT |
| `AWG_DNS` | `1.1.1.1,1.0.0.1` | DNS в клиентских конфигах |
| `AWG_ALLOWED_IPS` | `0.0.0.0/0,::/0` | Маршруты клиентов |
| `AWG_MTU` | `1420` | MTU интерфейса и клиентов |
| `AWG_PERSISTENT_KEEPALIVE` | `25` | Keepalive клиентов, секунд; `0` отключает |
| `UI_PORT` | `51821` | TCP-порт панели |
| `COOKIE_SECURE` | `false` | Установите `true`, если панель работает за HTTPS |
| `CLUSTER_ROLE` | `standalone` | Роль узла: `standalone`, `primary` или `replica` |
| `CLUSTER_NODE_ID` | значение `AWG_HOST` | Уникальное имя узла в кластере |
| `CLUSTER_SECRET` | пусто | Общий секрет кластера, минимум 32 символа |
| `CLUSTER_PEERS` | пусто | На primary — URL replica через запятую; на replica — URL primary |
| `CLUSTER_SYNC_INTERVAL_SECONDS` | `15` | Интервал фоновой сверки состояния |
| `CLUSTER_REQUEST_TIMEOUT_SECONDS` | `5` | Таймаут запроса к соседнему узлу |

Тонкие параметры обфускации (`AWG_JC`, `AWG_S1`, `AWG_I1`, параметры 3.1 и другие) перечислены в `.env.example`. Не меняйте их без необходимости: некорректные или несовпадающие значения разрывают соединение.

Параметры Compose применяются при первом старте и при их изменении. Случайно сгенерированные ключи и параметры не меняются от обычного перезапуска контейнера.

## Кластеризация серверов

Кластер использует схему **один primary + любое число replica**. Все изменения выполняются на primary; replica доступны для чтения, скачивания конфигов и создания бэкапа. После создания, отключения, переименования, удаления клиента или восстановления бэкапа primary немедленно отправляет новый снимок всем replica. Каждая replica дополнительно запрашивает состояние primary с заданным интервалом, поэтому пропущенная синхронизация автоматически восстанавливается.

Сгенерируйте один общий секрет:

```bash
openssl rand -base64 48
```

Пример `.env` primary:

```dotenv
AWG_HOST=vpn.example.com
CLUSTER_ROLE=primary
CLUSTER_NODE_ID=vpn-1
CLUSTER_SECRET='ОДИН_ОБЩИЙ_СЕКРЕТ'
CLUSTER_PEERS=http://10.0.0.12:51821,http://10.0.0.13:51821
```

Пример `.env` replica:

```dotenv
AWG_HOST=vpn.example.com
CLUSTER_ROLE=replica
CLUSTER_NODE_ID=vpn-2
CLUSTER_SECRET='ОДИН_ОБЩИЙ_СЕКРЕТ'
CLUSTER_PEERS=http://10.0.0.11:51821
```

Для каждого дополнительного replica меняются только `CLUSTER_NODE_ID` и адрес узла. Требования к сети:

- TCP-порт панели должен быть доступен между узлами; ограничьте его firewall-ом адресами кластера;
- через недоверенную сеть используйте HTTPS: секрет передаётся в Bearer-заголовке;
- на всех узлах должны совпадать `AWG_VERSION`, `AWG_ADDRESS`, DNS, MTU и тонкие параметры AWG;
- назначайте только один primary. При split-brain автоматического объединения конкурирующих изменений нет;
- для прозрачного failover используйте общий DNS, балансировщик или floating IP в `AWG_HOST`. Все узлы получают одинаковую серверную криптографическую идентичность и клиентские ключи.

При недоступности replica primary продолжает работать и повторяет синхронизацию. При недоступности primary replica продолжает обслуживать уже синхронизированные конфиги, но остаётся read-only. Для ручного failover остановите прежний primary, измените роль актуальной replica на `primary`, задайте ей остальные replica в `CLUSTER_PEERS` и перезапустите контейнер.

## Включение и отключение конфигурации

Кнопка питания в строке клиента исключает или возвращает его `[Peer]` в рабочий `awg0.conf`, после чего интерфейс применяется заново. Приватные ключи при отключении не удаляются. Удаление необратимо без бэкапа.

## Бэкап и перенос на другой IP

1. Нажмите **Скачать** в блоке «Переносимый бэкап».
2. На новом сервере скопируйте проект, создайте `.env` и задайте новый `AWG_HOST`.
3. Оставьте ту же `AWG_VERSION`, если хотите сохранить совместимость уже выданных конфигов.
4. Запустите `docker compose up -d --build`, войдите и нажмите **Восстановить**.

Файл `.awgbak` содержит серверный приватный ключ, PSK и приватные ключи клиентов. Храните его как секрет. `AWG_HOST`, внешний порт и сетевое устройство намеренно не используются из бэкапа: они берутся из Compose нового сервера. После восстановления скачанные заново конфиги получают новый `Endpoint`.

Если нужен полностью автоматический перенос без UI, можно также перенести каталог `data/`, изменить `AWG_HOST` и запустить Compose. Вне настроенного primary/replica-кластера не запускайте один и тот же бэкап одновременно на двух доступных серверах: у них будет одна криптографическая идентичность.

## Разработка и тесты

```bash
npm install
PASSWORD_HASH="$(node scripts/hash-password.mjs dev-password)" \
AWG_HOST=127.0.0.1 AWG_DRY_RUN=true npm run dev
```

Пароль для этого локального примера — `dev-password`.

В режиме `AWG_DRY_RUN=true` генерируется настоящий конфиг, но системный интерфейс не поднимается.

```bash
npm test
npm run typecheck
npm run build
```

## Безопасность

- Панель не имеет пароля по умолчанию и не стартует без валидного bcrypt-хеша.
- Сессия хранится в `HttpOnly`, `SameSite=Strict` cookie; после пяти неверных попыток вход временно блокируется.
- Для публичного доступа поставьте панель за HTTPS reverse proxy и задайте `COOKIE_SECURE=true`.
- Не публикуйте TCP-порт панели в интернет без firewall или reverse proxy.
- Внутренний endpoint репликации требует `CLUSTER_SECRET`; используйте уникальный случайный секрет и HTTPS либо изолированную сеть.
- Каталог `data/` и файлы бэкапа содержат приватные ключи.

## Обновление

```bash
docker compose build --pull
docker compose up -d
```

Перед обновлением скачайте бэкап. Версии исходников `amneziawg-go` и `amneziawg-tools` закреплены аргументами сборки в `docker-compose.yml`, чтобы повторная сборка была предсказуемой.
